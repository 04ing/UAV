## 五、潜在风险点

### 🔴 高风险

| # | 风险 | 影响 | 位置 |
|---|------|------|------|
| 1 | **定时器泄漏** | Jest worker 进程未能优雅退出（`updateMockTelemetry` 的 `setInterval` 和告警生成循环未在测试后清理），生产环境中若 PM2 reload 时可能残留旧定时器 | `djiApiAdapter.js` L279/L421 |
| 2 | **3 个路由 0% 覆盖** | `ai.js`、`meta.js`、`ops.js` 路由完全未测试，其中 `ops.js` 包含审计日志和用户管理，存在未发现的 Bug 风险 | `routes/ai.js`、`routes/meta.js`、`routes/ops.js` |
| 3 | **无并发测试** | 多架无人机同时上报遥测时的数据竞争未测试，`DataStore` 的文件写入非原子操作，并发可能丢失数据 | `data/dataStore.js` L53 `saveFile` |

### 🟡 中风险

| # | 风险 | 影响 | 位置 |
|---|------|------|------|
| 4 | **djiApiAdapter 覆盖率低** | 真实 DJI API 的 HTTPS 请求分支（L494-L558）和签名计算（L474-L483）未测试，接入真实无人机时可能出问题 | `djiApiAdapter.js` L474-L558 |
| 5 | **mock 定时器循环未测试** | `updateMockTelemetry` 中的电量消耗、自动返航、信号波动逻辑通过 setInterval 驱动，单元测试未覆盖这些异步逻辑 | `djiApiAdapter.js` L279-L407 |
| 6 | **文件 I/O 异常未测试** | `loadFile` 的 JSON 解析失败 catch 和 `saveFile` 的写入错误 catch 分支未覆盖，磁盘满或文件损坏时行为未知 | `dataStore.js` L35-L41, L53-L54 |
| 7 | **限流中间件未在真实流量下验证** | 测试中限流阈值已放宽（10000 次/秒），实际 300 次/15min 阈值可能导致正常用户被误限 | `server.js` 全局 limiter |
| 8 | **JWT Token 过期未测试** | Token 过期后的刷新机制和 401 响应未测试 | `middleware/auth.js` |

### 🟢 低风险

| # | 风险 | 影响 | 说明 |
|---|------|------|------|
| 9 | **无压力测试** | 高频遥测上报（>100 次/秒）下的系统表现未知 | 建议后续用 `autocannon` 做基准测试 |
| 10 | **前端未测试** | 前端页面（GIS、告警面板、工单管理）无自动化测试 | 建议后续引入 Playwright 做端到端 UI 测试 |
| 11 | **WebSocket 未测试** | 实时推送（遥测更新、告警推送）的 WebSocket 通道未覆盖 | 需要专门的 WebSocket 测试工具 |
| 12 | **路径遍历测试覆盖有限** | 仅测试了 `..%2F` 编码形式，未覆盖双重编码、Unicode 编码等绕过手法 | 建议添加更多攻击向量测试 |

### 6.1 优点

- **全流程覆盖**：从登录到坠毁告警的 15 个环节端到端验证，链路完整
- **故障模拟全面**：5 种故障类型全部覆盖，含触发/查询/清除/去重
- **参数校验充分**：7 个错误场景覆盖（缺参数/无效值/不存在资源）
- **安全防护验证**：路径遍历 403、无 Token 401 已验证
- **数据一致性**：上报数据与查询结果字段级比对

### 6.2 不足

- **分支覆盖率偏低（35.61%）**：主要因 djiApiAdapter.js 中大量异步循环和真实 API 分支未覆盖
- **3 个路由模块零覆盖**：ai.js / meta.js / ops.js 完全未测试
- **无并发/压力测试**：单线程串行测试无法发现并发问题
- **定时器泄漏**：Jest worker 未优雅退出，说明有未清理的定时器
